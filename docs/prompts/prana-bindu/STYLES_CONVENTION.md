# Стандартизация CSS/стилей для модулей приложения

## Что обсуждаем

Создание мини-библиотеки стилей на основе CSS Prana-Bindu, с единым
набором компонентов (панели, кнопки, инпуты, календари, drawer'ы,
таблицы, диалоги, табы, бейджи) и возможностью цветового
переопределения по модулю.

## Зачем

Сейчас в проекте несколько модулей (Prana-Bindu, OSINT, Gateway,
Trading, Bonds и т.д.), и у каждого свои CSS-правила. Есть общие
паттерны (панель с заголовком, кнопки `.xxx` / `.xxx-soft`,
календарь с accent-рамкой, диалоги), но они дублируются с разными
цветами. Нужна единая система: одинаковое поведение, разные акценты.

## Ключевые решения (черновик, обсуждаем)

1. **Одна тема на модуль-окно.**
   Каждое окно приложения имеет свою акцентную тему (Prana-Bindu —
   песочная, OSINT — синяя, Trading — красная и т.д.).
   Пользователь может переопределить цвета темы в настройках модуля.

2. **Общая библиотека стилей + акцентные переменные.**
   Компоненты описываются один раз через CSS-переменные:
     --module-accent
     --module-accent-soft
     --module-accent-rgb
   Конкретное значение задаётся на корне модуля
   (`.pb-page`, `.osint-page`, ...).

3. **N фонов на модуль (опция).**
   Каждая тема содержит предустановленный набор фонов
   (тёмный, светлый, кастомный), между которыми переключается
   пользователь. Хранится в localStorage или sync_settings модуля.

4. **Формат хранения: CSS-переменные + опциональный runtime-override.**
   Тема задаётся CSS-переменными на `.module-root`, значения
   подтягиваются из настроек при старте окна.

## Что должно быть в STYLES_CONVENTION.md

- Список обязательных CSS-переменных (`--module-accent`,
  `--module-accent-rgb`, `--module-bg`, `--module-surface`, ...).
- Список классов-компонентов (`.{mod}-panel`, `.{mod}-button`,
  `.{mod}-button-soft`, `.{mod}-input`, `.{mod}-calendar`,
  `.{mod}-drawer`, `.{mod}-tabview`, `.{mod}-badge-*`).
- Соглашение о нейминге: `.{mod}` — корневой, `.{mod}-x` — модификаторы.
- Как подключить тему: в файле модуля определить переменные,
  подключить общий `common-modules.css`.
- Как хранить настройки пользователя (какой файл, какая структура).
- Миграционный план: как перевести существующие модули
  (OSINT, Trading, ...) на общую систему.

## Исходный код для анализа

- `src/pages/PranaBinduPage/PranaBinduPage.css` — рабочий пример.
- `src/components/SIETCH/DatabasePage.css` — существующий OSINT-стиль.
- Посмотреть, что уже вынесено в `.pb-page`, `.pb-*`,
  `.osint-*`, и как совмещается с PrimeReact.

## Что НЕ входит

- Рефакторинг всех модулей сразу — сначала конвенция, потом миграция.
- Тёмная/светлая тема системы — только акценты и фоны модулей.

## Стратегия

1. Скопировать в чат: `01_COMMON_CONTEXT.md`, `PROJECT_STATE.md`,
   этот файл, `PranaBinduPage.css`, `DatabasePage.css`.
2. Обсудить черновик конвенции.
3. Написать `docs/prompts/_shared/STYLES_CONVENTION.md`.
4. Пилот: перевести Prana-Bindu на новую систему (без потери вида).
5. Мигрировать OSINT вторым — на нём проверим масштабируемость.

## Первый вопрос к чату

Какие CSS-переменные мы фиксируем как обязательные? Мой черновик:

  --module-accent            — основной акцент (например, prana-bindu - #d4a373, osint - #6ab2f2 )
  --module-accent-rgb        — RGB того же цвета (для color-mix)
  --module-accent-contrast   — цвет текста на accent (обычно #1a1a1a)
  --module-bg                — основной фон модуля
  --module-surface           — фон карточек/панелей
  --module-border            — цвет границ
  --module-text              — основной текст
  --module-text-muted        — вторичный текст (hint)

Для примеры можно взять цвета из этой темы Telegram, именно её я использовал в самом начала создания многомодульного приложеня, сохранять имена переменных необязательнно, но они дают понимание, какие цвета используются в базовой теме

  --tg-theme-accent-text-color: #6ab2f2;
  --tg-theme-bg-color: #17212b;
  --tg-theme-button-color: #5288c1;
  --tg-theme-button-text-color: #ffffff;
  --tg-theme-destructive-text-color: #ec3942;
  --tg-theme-header-bg-color: #17212b;
  --tg-theme-hint-color: #708499;
  --tg-theme-link-color: #6ab3f3;
  --tg-theme-secondary-bg-color: #232e3c;
  --tg-theme-section-bg-color: #17212b;
  --tg-theme-section-header-text-color: #6ab3f3;
  --tg-theme-subtitle-text-color: #708499;
  --tg-theme-text-color: #f5f5f5;

## Связанный чат

Компоненты (ProgressBar-блок, source-бейджи, drawer-секция,
badges-группа) — выносим в отдельный чат COMPONENTS.
STYLES_CONVENTION описывает только CSS-переменные и классы,
COMPONENTS — React-контракты и их использование.
