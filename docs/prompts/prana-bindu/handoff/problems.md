# Известные проблемы — Prana-Bindu

## П1. HR-баг старых dodofo-записей

**Симптом:** у 260 `run_facts` с `dodofo` **до 2026-09-30** поле `hr` = константа **144**.

**Причина:** баг на стороне сервера dodofo. Исправлен разработчиком 2026-09-30, но **старые данные не пересчитаны**. Mass-resync не помогает.

**Следствие:** графики пульса по этим тренировкам некорректны. В аналитике — либо исключать, либо помечать.

**Статус:** не исправлено (не наша зона).

## П2. GPS в Москве глушат (СВО)

**Симптом:** GPS-трек в центре Москвы часто невалиден (`gps_quality: poor` или `lost`).

**Следствие:** дистанция/темп считаются от **акселерометра**, не от GPS. Сам трек записывается — `Activity.polyline` отдаётся, но точек мало/они смещены.

**Классификация** (при импорте): `good` / `poor` / `lost`. Override — в деталях тренировки.

**Статус:** обходим через акселерометр + сохраняем GPS-трек как есть.

## П3. dodofo отдаёт `null` для продвинутых метрик

**Симптом:** провайдер dodofo возвращает ключи `vo2max`, `spo2_avg_pct`, `hrv_ms`, `fatigue`, `stress`, `mood` — но **значения всегда `null`**.

**Причина:** ограничение облака Huawei/Zepp. Не наша зона.

**Следствие:** в UI эти поля скрыты. Для их получения нужен **Zepp-direct** (прямая авторизация к API Zepp через `@dofek/zepp-client`).

**Статус:** TODO — Zepp-direct.

## П4. `run_facts.training_load` в `raw_json`

**Симптом:** `training_load` (TSS/ATL/CTL) хранится в `raw_json`, не отдельной колонкой.

**Следствие:** SQL-запросы для аналитики неэффективны, нельзя индексировать.

**Фикс:** Melange v37 — вынести в колонку.

**Статус:** запланировано (08 Melange v37).

## П5. Дедупликация на уровне БД

**Симптом:** одна тренировка может быть в БД **несколько раз** — `dodofo:11714` + `fit:21485879572` + `intervals-icu:i194901643`.

**Сейчас:** UI группирует по `(date, start_time ± 30 мин)` → одна строка, внутри вкладки источников. Дедупликация на уровне БД — v22+ (канонический `run_events` + `run_sources`).

**Проблема:** `sources_json` в `run_facts` не до конца внедрён.

**Статус:** частично (v22+). TODO — `sources_json` в `run_facts`.

## П6. Zepp-direct не реализован

**Симптом:** `dofekProvider.ts` — заглушка (`isAvailable()` читает `sync_settings`, `fetchWorkouts()` возвращает `[]`).

**Следствие:** VO2max, SpO2, HRV детально, гипнограмма сна — недоступны.

**Фикс:** доделать `DofekZeppProvider` поверх `regionDetector.ts` + `@dofek/zepp-client@0.1.44`.

**Статус:** TODO (07 Spice, после Push в ICU).

## П8. Handoff-by-button теряет DDL и детали Spice
**Симптом:** при генерации handoff по кнопке (2026-11-20) в `.md` попали только 6 из 29 DDL-таблиц Melange и только синтаксис ICU из 07 Spice. Детали (провайдеры, парсеры, sync, дедупликация) — отсутствуют.
**Причина:** 16-секционный handoffBuilder ограничен по объёму; 08_MELANGE.md (2776) и 07_SPICE.md (2201) не влезают целиком.
**Следствие:** при работе над v37 и Push в ICU придётся восстанавливать из `git show d37d02f:docs/prompts/prana-bindu/chats/...`.
**Статус:** зафиксировано в `techdebt.md` TD9/TD10. Не блокер — источник в git.

## П7. `prana_bindu.db` — токены только через safeStorage

**Напоминание:** все токены (`dodofo_token`, `intervals_api_key`, `zepp_app_token`, `zepp_credentials_json`) — **только** `safeStorage.encryptString`. В логи не выводить, в чат не копировать.

**Проверка:** `grep -rn "dodofo_token\|intervals_api_key\|zepp_app_token" src/ | grep -v "safeStorage"` — должно быть пусто (кроме чтения из `sync_settings`).

**Статус:** соблюдается, но проверять при каждом PR.
