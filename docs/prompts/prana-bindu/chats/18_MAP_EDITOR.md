# Направление 18: Картографический редактор и Карты

> Обновлено: 2026-10-22
> Статус: Этапы A+B закрыты. Story Generator (Этап C) — закрыт. Thresholds — C.1–C.4 закрыты, C.5 (эталонные треки) — в плане.

## Роль
Полноэкранный инструмент для визуализации GPS-треков, настройки стилей карты и трека, разметки тестовых отрезков для расчёта порогов (LTHR/HRmax), экспорта картинок (сторис). В перспективе — рисование эталонных маршрутов для сравнения пробежек неделя-к-неделе.

- Переключатель источников (fit / dodofo / icu / zepp).

### 3. `test_segments` + Thresholds (C.1–C.4) — ЗАКРЫТО
- **БД (v26)**: таблица `test_segments` (`run_fact_id`, `start_lat/lng`, `start_idx/end_idx`, `duration_type/value`, метрики: `distance_m`, `duration_sec`, `pace_sec_per_km`, `hr_avg/max`, `hr_drift_pct`, `cadence_avg`, `note`, `created_at`). FK → `run_facts.id` (CASCADE).
- **Репозиторий** `testSegmentsRepo.ts`: `create`, `list`, `listForRun`, `delete`.
- **Кандидаты** `testSegmentCandidates.ts`: `findTestSegmentCandidates(db, opts)` — по всем `run_facts` с потоками за окно. Дедупликация по `(date, start_time/30min)` с приоритетом источников потоков: `fit > zepp > tcx > dodofo`. Возвращает `coveragePct`, `isClean`, `canSave`, `alreadySaved`. `diagnoseCandidates` — счётчики для UI.
- **UI**: `TestCandidatesDialog.tsx` — таблица кандидатов с чекбоксами, автовыбор «готовых», кнопка «Сохранить выбранные».
- **Расчёт LTHR** `computeThresholds`:
  - Приоритет: `test_segments` длительности `lthrTestDuration` (5/10/15/20/30 мин) за `windowDays`.
  - Агрегация: медиана всех или среднее топ-N (настройка `topN`).
  - Фильтры: чистота (`|drift| < 5%`), интенсивность (`hr_avg ≥ pct × HRmax`, настройка `onlyIntensePct` от 0 до 90%).
  - Минимум тестов (`minTests`, по умолчанию 3). Если меньше — fallback на автопоиск (лучший 20-мин отрезок по всем streams × 0.95).
  - Коэффициенты LTHR по длительности: 5м×0.88, 10м×0.91, 15м×0.93, 20м×0.95, 30м×1.0.
  - Диагностика в результате: `testsTotal`, `skippedClean`, `skippedIntense`, `method`, `hrRange`.
- **Timeline** `computeThresholdsTimeline`: rolling-окно (30/60/90 дней), шаг 14 дней. Возвращает массив точек `{date, lthr, hrmax, resthr, testsUsed, source}`.
- **UI в `ProfilePanel`**:
  - «Рассчитать из фактов» с настройками: окно, длительность LTHR-теста, метод (медиана/топ-3/топ-5), фильтры (чистота, интенсивность 0–90%), мин. тестов (1/2/3/5).
  - Бейдж: зелёный «✓ по N тестам» (если N ≥ minTests), жёлтый «⚠ по 1–2 тестам (мало)», серый «автопоиск».
  - Разброс HR на отобранных тестах (`hrRange`).
  - Блок «📈 Динамика порогов» (`ThresholdsTimelineChart`): 6/12/24 мес., окно 30/60/90 дней, чекбоксы LTHR/HRmax/RestHR.
- **История**: `threshold_history` (v25) — записывается при каждом расчёте.

### 4. Thresholds: ограничения тестирования
- **Реальный LTHR-тест — не чаще 1 раза в неделю** (физиология: 48–72 ч восстановления после 20 мин на усилии 8/10).
- **Следствия**: за 60-дневное окно — максимум 8–12 тестов. При `minTests=3` первые 3 недели LTHR = автопоиск, с 4-й — по тестам.
- **Не делать автозапуск** «сохранить все чистые» — БД замусорится разминочными отрезками (на данных 2026-10-22: из 11 «тестов» только 1 прошёл фильтр ≥88% HRmax).
- **Отделять «реальные тесты» от «кандидатов»**: поле `kind` в `test_segments` (`intentional` | `candidate`). Планируется в v27.
- **Методика правильного теста**:
  1. Разминка 15 мин (HR 130–145).
  2. 20 мин на усилии 8/10 (HR 165–175 при HRmax ~184).
  3. Заминка 10 мин.
  4. Точка старта = **начало этих 20 минут** (не старт маршрута).
- **Что не считается тестом**: первые 20 мин после старта, HR < 85% HRmax, дрейф > 5%, лёгкие/восстановительные.

### 6. Автоопределение пробежек по эталонам (C.5) — ЗАКРЫТО
- **Пороги автоопределения**: Настраиваемые ползунки в «Стиле» (coverage used/similar, ratio loop/linear, медиана отклонения).

- **Список треков**: секции «Пройдено / Похоже / Без маршрута». Переключатель на плоский список.
- **Фильтр**: кнопка «🔍 Показать пробежки» в карточке атома.

### C.9 — Прокси тайлов OSM через `protocol.handle` (Исследование)

#### Кеширование тайлов (отложено)
- Попытки через `addProtocol` / IndexedDB в рендерере ломают WebGL.
- Следующий шаг — `protocol.handle` в main-процессе Electron, сохранение в `userData/pb-tile-cache`.
- OSM блокирует автоматические запросы без валидного User-Agent/Referer (проверено 2026-10-21). Carto требует API-ключ.

- **Проблема:** Прямые запросы с `origin: localhost:5173` к `a.tile.openstreetmap.org` блокируются CORS в рендерере. Ранее попытка `protocol.handle('pb-tile', …)` + `net.fetch` давала **403** от OSM.
- **Возможные причины 403 (проверить по порядку):**
  1. `User-Agent` не передаётся / дефолтный (`Electron/44.x`). OSM требует идентифицируемый UA с контактом (например, `PranaBindu/1.0 (contact@email)`).
  2. Нет `Referer: https://www.openstreetmap.org/` — OSM отсекает запросы без реферера.
  3. Слишком высокая частота (правило 1 req/sec на tile-сервер). MapLibre при зуме/панорамировании долбит параллельно.
  4. Одновременные запросы к `a./b./c.tile.openstreetmap.org` — политика OSM запрещает параллельные запросы к разным поддоменам.
- **Альтернативы (если OSM продолжит блокировать):**
  - **Stadia Maps** (Alidade Smooth Dark) — бесплатный dev-ключ, 200k тайлов/мес, CORS `*`, растровый. Прямой URL в `mapStyles.ts`, без прокси.
  - **OpenFreeMap** (`tiles.openfreemap.org/styles/dark`) — полностью бесплатно, без ключа, но **векторные тайлы**. Потребует переписать `getOsmStyleObject` (raster → style URL) и убрать слайдеры `raster-*` из UI.
  - **Thunderforest / MapTiler** — условно-бесплатно, с ключом.
- **Что делать сейчас:** зафиксировать как отдельную сессию. Пока работаем с OSM-тайлами «как есть» — при быстром зуме CORS-ошибки в консоли, но карта всё равно загружает большинство тайлов (некоторые догружаются с retry).
- **MVP:** Stadia Maps (5 минут настройки) → если не устроит внешний вид, копать `protocol.handle` с правильным UA/Referer.
- **Бонус (если прокси заработает):** кеш на диск в `userData/pb-tile-cache`, что снизит нагрузку на OSM и ускорит повторную загрузку.

### C.10 — Настраиваемое количество контрольных точек (КП) для кругов
- **Текущее состояние:** В `coverageIndex.ts` для расчета `repeats` жестко зашиты 4 КП (на 20%, 40%, 60%, 80% длины эталона).
- **Задача:** Добавить в UI («Стиль» → «Пороги автоопределения») слайдер «Количество КП» (от 3 до 10).
- **Зачем:** Для сложных маршрутов (например, «восьмерка» или круг с глубоким заходом в парк) 4 точки могут пропустить петлю. Больше точек = точнее расчет, но чуть медленнее batch-обработка.
- **Реализация:** Передавать `cpCount` в `computeDeviationFast`, вычислять `cpFractions` динамически (шаг = 1 / cpCount).

### C.11 — Исследование бесплатных векторных карт (вместо OSM raster)

**Проблема:** OSM raster-тайлы блокируют CORS и требуют прокси, который упирается в 403. Растровые альтернативы (CartoDB) требуют ключ. Векторные тайлы решают проблему CORS и дают больше контроля над стилем.

**Кандидаты (исследовать):**

| Сервис | Модель | Плюсы | Минусы |
|---|---|---|---|
| **MapToolkit.org** | Free, без API-ключа | Production-grade, CORS, MapLibre-стили из коробки, 3D-рельеф. Бесплатно для некоммерческих и малых коммерческих (<€1M выручки, <10 сотрудников). Запрещены прокси, офлайн-генерация, массовый скрапинг. | Нельзя использовать как «прокси» для OSM. Нужно менять `getOsmStyleObject` на style URL. |
| **Protomaps.com** | Open-source, self-host | PMTiles — один файл на весь мир, хостится на S3/Cloudflare R2. Нет API-ключей и лимитов. Бесплатно для некоммерческого использования. | Нужно самостоятельно хостить файл (или брать daily download). Первоначальная настройка сложнее. |
| **OpenFreeMap.org** | Free, без ключа | Уже упоминался, векторный, CORS. | Только векторные стили, нужно переписывать рендер. |
| **MapTiler / Stadia** | Freemium, с ключом | Простота, красивый дизайн. | Лимиты, ключ, зависимость от вендора. |

**Что проверить в первую очередь:**
1. **MapToolkit** — самый быстрый путь: заменить `getOsmStyleObject` на `https://tiles.maptoolkit.org/...` (точный URL из docs). Проверить, работает ли CORS в Electron-рендерере без прокси.
2. **Protomaps** — если MapToolkit не подойдёт по лицензии: скачать PMTiles, захостить локально или на R2, подключить через `pmtiles` протокол в MapLibre.

**Важно:** при переходе на векторные тайлы слайдеры `raster-brightness/saturation/contrast` перестанут работать (они только для raster). Нужно будет либо убрать их из UI, либо применять CSS-фильтр к контейнеру карты (тогда пострадает и трек).

**MVP:** заменить `getOsmStyleObject` на style URL MapToolkit (1 файл, ~20 строк). Если стиль не устроит — переходить на Protomaps + кастомный стиль.

# Направление 18: Картографический редактор и Тестовые сегменты

> Обновлено: 2026-10-19
> Статус: планирование.

## Роль
Полноэкранный инструмент для визуализации GPS-треков, создания геозон (тестовых сегментов) и интеграции их с расчётом порогов (LTHR).

## Проблема
Сейчас карта в `RunStreamsDrawer` — это режим "только чтение". Мы не можем ставить маркеры, выделять отрезки и сохранять их. Для точного расчёта порогов (LTHR) нам нужны контролируемые 20-минутные отрезки на постоянных маршрутах.

## Цель
1. Создать окно/диалог `RouteMapEditor` с большой картой (MapLibre).
2. Добавить инструменты разметки: маркер старта, выбор длительности (5, 10, 20 мин).
3. Реализовать «магнит» (snap-to-track) для привязки клика к реальным точкам пробежки.
4. Сохранять найденные сегменты в БД (Melange v26) и использовать их в `computeThresholds`.

## Модель данных (Melange v26)
```sql
CREATE TABLE IF NOT EXISTS test_segments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  label TEXT NOT NULL,
  start_lat REAL NOT NULL,
  start_lng REAL NOT NULL,
  radius_m REAL NOT NULL DEFAULT 30,
  duration_sec INTEGER NOT NULL,     -- 300, 600, 1200
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

## Архитектура UI
- **Карта:** `maplibre-gl`. 
- **Слои:** 
  - Базовая карта (OpenFreeMap).
  - Тепловая карта (`heatmap` слой из всех треков).
  - Активный трек (линия, по которой кликаем).
- **Инструменты:** 
  - Клик по треку → установка маркера старта (snap к ближайшей точке `latlng`).
  - Отображение длины отрезка и среднего пульса в реальном времени (Haversine).

## Алгоритм расчёта в `thresholds.ts`
1. Ищем в `test_segments` активные тесты.
2. Для каждой пробежки проверяем, проходит ли она через `start_lat/start_lng` (радиус `radius_m`).
3. Если да — берём отрезок длительностью `duration_sec` от точки входа.
4. Считаем средний пульс. Для 20-минутного: `LTHR = avg_hr * 0.95`.
5. Если тестов нет — падаем обратно на текущий алгоритм (поиск лучшего 20-мин отрезка во всех пробежках).
