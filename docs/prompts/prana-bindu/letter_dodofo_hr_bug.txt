ПРОБЛЕМА

В ответе /streams поле hr на некоторых тренировках возвращает не массив
пульса, а константу. При этом:

  1) max_hr_bpm совпадает с этой константой;
  2) hr_curve на всех окнах (3с, 5с, 15с, ..., 3600с) тоже равен ей;
  3) hr_zones в таком случае складывается в одну зону с 100 % времени.

Похоже, что при отсутствии посекундного HR-канала значения подменяются
значением max_hr_bpm. Это лишает смысла анализ по пульсу через API.

Как заполнить плейсхолдеры
[ACTIVITY_ID_МАРАФОН] — id марафонской тренировки. У вас в run_facts id=85, date=2026-09-27. Посмотрите external_id:

bash
sqlite3 ~/.config/wetothemoon-electron/prana_bindu.db \
  "SELECT id, date, actual_km, external_id FROM run_facts WHERE id = 85;"
Скорее всего будет что-то вида dodofo:11720 — число после dodofo: и есть activityId.

[ACTIVITY_ID_7КМ] — аналогично для id=15 (26.09). Судя по данным, это dodofo:11714.

Когда отправлять
Вы сказали: «когда у нас будет с чем сравнить». Полностью согласен. План:

Сначала — реализуем pb:sync-thresholds (сегодня).

Потом — дойдём до wellness или до FIT/TCX.

Когда появится второй источник (FIT-файл с тех же дней) — добавим в письмо строчку:

При сравнении с FIT-файлом с тех же часов (прилагаю), avg HR = 152,
max HR = 165, а ваш API отдаёт 174 константой. Это подтверждает баг
на стороне dodofo.

Это очень сильный аргумент. Без второго источника они могут сказать «у вас часы так записали» — с FIT-файлом спорить нечем.
