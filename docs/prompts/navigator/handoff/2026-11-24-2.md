## ⚠️ Открытые вопросы

### 1. 🐞 `syncConversations` после `conversation-saved` — не протестировано

Последняя правка в Sidebar: после `conversation-saved` вызывать `syncConversations` (полный sync adapter) с debounce 1.5с. Это должно автоматически переставлять диалог наверх без ручного Sync.

**Не проверено.** См. «С чего начать следующую сессию» → Тест B.

**Если не работает:**
- Проверить `syncDebounceRef` в Sidebar (grep).
- Проверить, что `syncConversations` определён до `useEffect` (иначе ESLint/TS).
- Проверить `useRef` в импорте React.

### 2. 🐞 Adapter видит 191/261 (scroll cap GigaChat)

GigaChat отдаёт ~190 диалогов через DOM. 70 остальных — `position=NULL`, внизу Recent.

**Не блокер MVP.** Разбирать отдельно:
- `page.mouse.wheel()` вместо `scrollTop` (реальный wheel-событие может триггерить паттерн GigaChat).
- Или внутренний API GigaChat (`/api/sessions?offset=N`) — reverse-engineering, риск.

### 3. 🐞 `syncMessages` блокирующий IPC (15–20 сек)

Mutex защищает от race, но UI висит в `⟳` до возврата. Переделать на event-based:
- `syncMessages` → `{ started: true }` сразу.
- Результат — `navigator:sync-finished` / `navigator:sync-error`.
- Sidebar подписывается, снимает `⟳` по событию.

### 4. 🐞 `syncConversation` не пишет `position`

Новые диалоги из `navigator:send` имеют `position=NULL` → уезжают вниз Recent. Следующий `sync-conversations` поправит. **Не блокер.**

Альтернатива — расширить `syncConversation` параметром `opts.position`.

### 5. 🐞 Mirror включить позже

`archiveConversationsNotIn` в коде, вызов **закомментирован** в handler (строки 228–231). Включить после решения scroll cap. Пока phantom диалоги остаются в UI — не страшно (пользователь видит реальные).

## 🐞 Что НЕ делать (уроки сессии)

1. **Не прыгать `scrollTop = scrollHeight`** — IntersectionObserver не рендерит средние строки. Инкрементальный шаг 60% viewport.
2. **Не собирать DOM после скролла** — favorites размонтируются. Собирать **во время** скролла.
3. **Не путать `[class*="Row"]`** — матчит и `RowLink`, и `Row`. Нужно `[class*="Row-sc-"]`.
4. **Не забывать `migrateToV11` в оркестратор** — массив в `db.ts`, не в `GatewayCacheService.ts`.
5. **Не доверять `page.goto` на SPA** — `ERR_ABORTED` это норма, глушить только её.
6. **Не вызывать `syncMessages` из Page и Sidebar одновременно** — race → порча данных. Mutex + URL verify + UI guard.
7. **Не включать mirror без проверки** — ошибочно архивировал 89 реальных.

## 📚 Уроки сессии

1. **Виртуализация GigaChat** — favorites сверху размонтируются при скролле. Собирать **только во время** скролла.
2. **Substring-матч классов** — `[class*="Row"]` матчит `RowLink`. Нужно `[class*="Row-sc-"]`.
3. **`page.goto` на SPA** — `ERR_ABORTED` норма (старый фрейм не отпущен). Глушить только её.
4. **Оркестратор миграций** — массив `{version, apply}` в `db.ts` (не `GatewayCacheService.ts`). Пропуск записи → пустой UI.
5. **Mirror-archive** — опасная штука. Порог `>50` не спасает от glitch scroll. Отключён.
6. **`data-da_favorite`** — на button внутри `Row-sc-`, не на `<a>`. Путь: `a → closest(Row-sc) → querySelector([data-da_favorite])`.
7. **Порядок GigaChat = position из DOM**. `last_message_at` NULL у старых, `updated_at` = время парсинга. Без `position` сортировка бессмысленна.
8. **Race-fix** — нельзя вызывать `syncMessages` из двух мест. Mutex + URL verify + UI guard. Иначе 32 сообщения диалога A пишутся в B.
9. **Позиция после send** — `conversation-saved` обновляет `updated_at`/сообщения, но не `position`. `position` только через `sync-conversations`. Отсюда debounced sync после send.

### ✅ Тест B — ПРОЙДЕН (2026-11-25)

Диалог «Автоматизация email» (`01a2031a`) после send переехал на `pos=0, pinned=1` **автоматически, без ручного Sync**.

**Механика:**
1. `navigator:send` → `done` → `syncConversation` → эмит `conversation-saved`
2. Sidebar ловит через `onConversationSaved` → `refreshConversations` (мгновенный) + debounce 1.5s
3. Через 1.5s `syncConversations` → adapter перечитывает `position` из DOM
4. `setConversationPositionAndPinned` → БД → Sidebar рефрешит → диалог наверху

**Время:** ~15–20 секунд (1.5s debounce + 10–15s adapter scroll).

**Побочный эффект:** страница GigaChat скроллится вниз-вверх во время `syncConversations` (adapter проходит сайдбар). Приемлемо для MVP.

### 🐞 Нестабильность scroll в adapter — техдолг

В одном логе adapter вернул **184** диалога, в следующем (через 15s) — **262**. GigaChat рендерит по-разному в зависимости от позиции page и текущего DOM. `pos` правильный для видимых, но количество плавает.

**Не блокер:** порядок корректен для всех, кого adapter видит. 70–80 старых диалогов могут отсутствовать в каком-то из вызовов → уезжают в конец Recent через `COALESCE(999999)`. Следующий sync может их «поймать».

**Разбирать отдельно** (не в этой итерации):
- `page.mouse.wheel()` вместо `scrollTop`
- Или внутренний API GigaChat
- Или увеличить `iterations` в scroll-цикле до 200
