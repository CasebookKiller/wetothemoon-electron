## ✅ Сделано в этой сессии (2026-11-25)

### 1. Тест B — ПРОЙДЕН ✅

Диалог «Автоматизация email» (`01a2031a`) после send переехал на `pos=0, pinned=1` **автоматически, без ручного Sync**.

**SQL подтверждение:**
```
01a2031a-...|Автоматизация email...|pinned=1|pos=0|upd=2026-11-25 08:23:09  ← переехал
01a21056-...|Описание Opencode.ai...|pinned=1|pos=1
01a20971-...|Без названия|pinned=1|pos=2
```

**Механика автоперестановки:**
1. `navigator:send` → `done` → `syncConversation` → эмит `conversation-saved`
2. Sidebar ловит через `onConversationSaved` → `refreshConversations` (мгновенный) + debounce 1.5s
3. Через 1.5s `syncConversations` → adapter перечитывает `position` из DOM
4. `setConversationPositionAndPinned` → БД → Sidebar рефрешит → диалог наверху

**Время:** ~15–20 секунд (1.5s debounce + 10–15s adapter scroll).

**Побочный эффект:** страница GigaChat **скроллится вниз-вверх** во время `syncConversations` (adapter проходит сайдбар). Пользователь замечает движение. Приемлемо для MVP.

### 2. Race-fix — подтверждён на двух кликах

**Лог из сессии:**
```
Клик на 01a20971 → START 1 раз → parsed messages: 32 → syncConversation OK
Клик на 01a2031a → START 1 раз → parsed messages: 4  → syncConversation OK
```

Разные числа (32 vs 4) = парсинг **своего** диалога, не чужого. **Порча данных устранена.**

Три защиты работают:
- Mutex `activeSyncs: Set<profileId>` в handler
- URL verify (`page.url().includes(convId)` перед парсингом)
- Page больше не вызывает `syncMessages` (было 3× на клик → 1×)

## 🐞 Технический долг (не MVP-блокеры)

### 1. Нестабильность scroll в adapter

**Симптом:** в одном логе — **184** диалога, в следующем (через 15s) — **262**. GigaChat рендерит по-разному в зависимости от позиции `page` и текущего DOM.

**Причины (гипотезы):**
- GigaChat рендерит по-разному, когда page на разных диалогах
- Virtual scroll капризен
- Возможно, при `pos=0` (на верху списка) скролл стартует «с нуля» и докручивает больше

**Не блокер:** порядок корректен для видимых. 70–80 старых диалогов могут отсутствовать в каком-то из вызовов → уезжают в конец Recent через `COALESCE(999999)`. Следующий sync может их «поймать».

**Варианты решения (разбирать отдельно):**
- `page.mouse.wheel()` вместо `scrollTop` (реальный wheel может триггерить паттерн GigaChat)
- Увеличить `iterations` в scroll-цикле до 200
- Или внутренний API GigaChat (`/api/sessions?offset=N`) — reverse-engineering, риск

### 2. `syncMessages` блокирующий IPC (15–20 сек)

Mutex защищает от race, но UI висит в `⟳` до возврата. **Переделать на event-based:**
- `syncMessages` → `{ started: true }` сразу
- Результат — событие `navigator:sync-finished` / `navigator:sync-error`
- Sidebar снимает `⟳` по событию

### 3. `syncConversation` не пишет `position`

Новые диалоги из `navigator:send` имеют `position=NULL` → уезжают вниз Recent. Следующий `sync-conversations` поправит (мы это видим в Тесте B). **Не блокер.**

Альтернатива — расширить `syncConversation` параметром `opts.position`.

### 4. Mirror-archive — отключён, включить позже

`archiveConversationsNotIn` в коде `GatewayCacheService.ts`, вызов **закомментирован** в `navigatorHandlers.ts:228–231`. Ошибочно архивировал 89 реальных диалогов (было в сессии 24.11). Включить после решения scroll cap.

### 5. Второй sync после send (debounce 1.5s) — не мгновенный

UX: диалог переезжает через 15–20 сек. Для MVP ок. Если раздражает — уменьшить debounce до 500ms.

### 6. `page.mouse.wheel` вместо `scrollTop`

Не проверено. Может решить scroll cap и уменьшить нестабильность. Разбирать при следующем заходе в adapter.

## 📚 Уроки сессий 24–25.11

1. **Виртуализация GigaChat** — favorites сверху размонтируются при скролле. Собирать **только во время** скролла.
2. **Substring-матч классов** — `[class*="Row"]` матчит `RowLink`. Нужно `[class*="Row-sc-"]`.
3. **`page.goto` на SPA** — `ERR_ABORTED` норма. Глушить только её.
4. **Оркестратор миграций** — массив `{version, apply}` в `db.ts` (не `GatewayCacheService.ts`). Пропуск записи → пустой UI.
5. **Mirror-archive** — опасная штука. Порог `>50` не спасает от glitch scroll. Отключён.
6. **`data-da_favorite`** — на button внутри `Row-sc-`, не на `<a>`.
7. **Порядок GigaChat = position из DOM**. `last_message_at` NULL у старых, `updated_at` = время парсинга. Без `position` сортировка бессмысленна.
8. **Race-fix** — нельзя вызывать `syncMessages` из двух мест. Mutex + URL verify + UI guard. Иначе 32 сообщения диалога A пишутся в B.
9. **Позиция после send** — `conversation-saved` обновляет `updated_at`/сообщения, но не `position`. `position` только через `sync-conversations`. Отсюда debounced sync после send (Тест B подтвердил).
10. **Scroll cap в GigaChat** — adapter видит 184–262 в зависимости от рендера. Не блокер для MVP, но техдолг.
