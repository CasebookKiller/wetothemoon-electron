## ⚠️ Открытые вопросы (для следующей сессии)

### 🐞 1. Проверить mirror — не переусердствовали ли

**89 archived** — это phantom или adapter их просто не видит?

**Тест:** возьми 2–3 `archived=1` id и открой в браузере GigaChat:

```bash
sqlite3 ~/.config/wetothemoon-electron/gateway.db "
  SELECT id, title FROM conversations
  WHERE profile_id='p_mwnqhvvi_rm0d' AND archived=1
  ORDER BY updated_at DESC LIMIT 5;
"
```

Для каждого открой: `https://giga.chat/sessions/<id>`
- **404 / редирект** → phantom, всё правильно.
- **Открывается** → adapter miss, mirror слишком агрессивный — откатывать `UPDATE ... SET archived=0` и разбираться со scroll.

**Быстрый откат** (если открываются):

```bash
sqlite3 ~/.config/wetothemoon-electron/gateway.db "
  UPDATE conversations SET archived = 0
  WHERE profile_id='p_mwnqhvvi_rm0d' AND archived = 1;
"
```

### 🐞 2. `conversation-saved` event — не сделано

Разблокирует автопоявление нового диалога после `navigator:send` без ручного Sync (~10 мин).

- `preload.ts`: `onConversationSaved(cb)` (по образцу `onChunk`).
- `navigator.d.ts`: `NavigatorConversationSaved { profileId, convId, count }`.
- `navigatorHandlers.ts`: в `navigator:send` после `cache.syncConversation(...)` → `event.sender.send('navigator:conversation-saved', { profileId, convId, count })`.
- `NavigatorSidebar.tsx`: `useEffect`-подписка → `refreshConversations(selectedId)`.

### 🐞 3. Legacy через `navigator:send` / `sync-messages` — без `position`

`syncConversation` не пишет `position`. Новые диалоги из нашего `send` получают `position = NULL` → уедут вниз. Не блокер:
- либо `syncConversation` расширить `opts.position`,
- либо следующий `sync-conversations` это поправит (adapter вернёт position).

### 🐞 4. `syncMessages` блокирующий IPC (15–20 сек)

Sidebar висит в `⟳`, UI не респонсивен. MVP — ок. Потом: event-based (`started: true` + `navigator:sync-finished`).

### 🐞 5. DeepSeek cookies (Этап 1.5)

Перед реализацией `DeepSeekAdapter.sendMessage`:
- Проверить persistence `userDataDir` в `ProfileService` — DS cookies должны сохраняться между запусками, иначе капчи чаще.

## 📚 Уроки сессии

1. **Виртуализация GigaChat** — favorites (сверху) размонтируются при скролле вниз. Собирать **только во время скролла**, не в конце.
2. **Substring-матч классов** — `[class*="Row"]` матчит и `RowLink`, и `Row`. Нужно `[class*="Row-sc-"]` или `closest` + fallback `parentElement`.
3. **`page.goto` на SPA** — `ERR_ABORTED` это норма (старый фрейм не отпущен). Глушить именно эту ошибку, не другие.
4. **Оркестратор миграций** — не в `GatewayCacheService.ts`, а в `db.ts` (массив `{version, apply}`). При добавлении колонки: (a) файл миграции, (b) `SCHEMA_VERSION` bump, (c) **запись в массив** — пропуск (c) → пустой UI.
5. **Mirror-archive** — безопасный способ скрыть phantom: `archived=1` не удаляет, `archived=0` возвращает. Порог `>50` защищает от glitch scroll.
6. **`data-da_favorite` на button**, не на `<a>` — путь `a → closest(Row-sc) → querySelector([data-da_favorite])`.
7. **Порядок GigaChat = position из DOM**. `last_message_at` не парсим (NULL у старых), `updated_at` = время нашего парсинга (одна секунда у batch). Без `position` сортировка бессмысленна.
