## 🐞 Текущий баг: HTML в user-сообщениях

**Симптом:** при клике на диалог история загружается, но сообщения **пользователя** показывают сырые теги `<p>...</p>`, тогда как ответы ассистента рендерятся нормально.

**Причина:** В `src/pages/NavigatorPage/NavigatorChat.tsx` в блоке рендера сообщений стоит жесткое условие:
```tsx
{m.role === 'user' ? (
  <span style={{ whiteSpace: 'pre-wrap' }}>{m.text}</span>
) : m.format === 'html' ? (
  <div dangerouslySetInnerHTML={{ __html: m.text }} />
) : ...}
```
Для user-сообщений мы **всегда** рендерим `<span>` с текстом, даже если `format === 'html'`.

**План фикса (на завтра):**
1. В `NavigatorChat.tsx` убрать `m.role === 'user'` из условия.
2. Рендерить user-сообщения точно так же, как assistant, **если `format === 'html'`**.
3. *Альтернатива (проще):* в `navigatorHandlers.ts` (`navigator:get-messages`) для `role === 'user'` принудительно делать `format: 'text'` и вырезать HTML-теги (например, через `textContent`, если бы мы брали его, но мы сохранили HTML).
4. Рекомендую **вариант 1** (универсально):
```tsx
{m.format === 'html' ? (
  <div className="navigator-markdown" dangerouslySetInnerHTML={{ __html: m.text }} />
) : m.format === 'markdown' ? (
  <div className="navigator-markdown" dangerouslySetInnerHTML={{ __html: renderMarkdown(m.text) }} />
) : (
  <span style={{ whiteSpace: 'pre-wrap' }}>{m.text}</span>
)}
```
*(И для user-сообщений применять `alignSelf: 'flex-end'` как раньше).*

### 🐞 Fix 7 — SVG в markdown гигантского размера

**Симптом:** GigaChat inline SVG-иконки (стрелки, копирование) растягиваются на всю ширину сообщения.

### 🐞 Fix 8 — Сортировка диалогов «как в GigaChat» (position)

**Симптом:** favorites блок появился, но порядок внутри Recent не совпадает с GigaChat.

**Причина:** `listConversations` сортирует `COALESCE(last_message_at, updated_at) DESC`. У старых диалогов `last_message_at` = NULL → падает на `updated_at` = **время нашего парсинга**, а не сообщения. Отсюда сдвиг: старый диалог, спарсенный позже, оказывается сверху.

**Fix (миграция v11):**
1. `ALTER TABLE conversations ADD COLUMN position INTEGER`.
2. Adapter возвращает `position` = индекс в `collected` Map (DOM order = порядок GigaChat, favorites 0..N, recent N+1..).
3. `cache.setConversationPosition(convId, position)` + вызов в handler `sync-conversations`.
4. `listConversations`: `ORDER BY pinned DESC, COALESCE(position, 999999) ASC, COALESCE(last_message_at, updated_at) DESC`.

**Semantics:**
- `pinned DESC` — на случай старых записей с `position=NULL`.
- `position ASC` — точный порядок GigaChat для всех новых.
- `last_message_at DESC` — fallback для legacy до v11.

**Не ломает:** `navigator:send` (новые диалоги получат `position=NULL` → попадут вверх Recent по `last_message_at` — это ок).
