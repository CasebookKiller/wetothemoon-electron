## Два пути handoff (важно)

| Путь | UI | IPC | Сервис | Выход |
|---|---|---|---|---|
| **Б (основной)** | `TopControlPanel` dropdown модулей | `gateway:export-handoff` | `handoffBuilder.ts` | `userData/handoff/handoff-*.md` |
| **А (второй)** | `GatewayChatHeader` «Экспорт продолжения» | `gateway:export-continuation` | `contextBuilder.ts` | `userData/continuation/continuation-*.md` |

**Путь Б** — 16 секций, `MODULE_MAP[moduleId]`, `kindLimit`, intent-файлы (`handoff/*.md` + `COMMON_CONTEXT.md`/`PROJECT_STATE.md`/`00_MASTER_INDEX.md` через `readModuleRoot`).
**Путь А** — manifest (`CONTEXT_MANIFEST`) + `workspaceKeys`, `contextBuilder.ts` → `context_nodes` chain.

**Объединение путей** — в roadmap «Следующие сессии». Пока оба живые, не мешают. `scripts/export-continuation-prompt.mjs` — CLI для Пути А (не трогаем).

## П1-fix-B — сайдбар из cache, не live

**Симптом (П1a/П1b):** при switch профиля Chrome закрывается, диалоги пропадают (пустой список).

**Фикс (часть B):**
- Сайдбар из `cache.listConversations()` (БД), не live из Chrome.
- Бейдж профиля в каждом диалоге (какой профиль его создал).
- Live-подгрузка — только для **активного** профиля, чтобы не терять диалоги при switch.

**Файл:** `GatewaySidebar.tsx` + IPC `gateway:get-conversations` (сейчас идёт live из Chrome, надо перевести на cache).

**Не делаем сейчас** — после BrowserPool (П1a). Фикс B без фикса A не имеет смысла (Chrome всё равно закрывается).
