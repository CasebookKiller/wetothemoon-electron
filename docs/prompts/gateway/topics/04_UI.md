## JSON-инструкции от LLM (долгосрочно)

**Идея:** приложение считывает ответы LLM в JSON с инструкциями по правке intent-файлов и применяет их.

**Формат (черновик):**
```json
{
  "edits": [
    {
      "file": "docs/prompts/gateway/topics/01_PROVIDERS.md",
      "find": "...",
      "replace": "...",
      "reason": "..."
    }
  ],
  "meta": { "task": "...", "session": "..." }
}
```

**Применение:**
- LLM отдаёт JSON → UI показывает diff-превью → пользователь подтверждает → правки применяются.
- Если `find` не найден — предупреждение, не применять.

**Связь с handoff:** LLM получает handoff → отвечает JSON-инструкциями → UI применяет → следующий handoff уже с обновлёнными файлами.

**Приоритет:** долгосрочно. После UI-редактора.
**Файл:** `src/main/services/gateway/intentEditor.ts` (новый) + IPC `gateway:apply-intent-edits`.

## Профиль-switch без auto-launch (2026-11-21)

`GatewayAccountsDialog`: клик по строке = **только** `switchProfile(id, { launch: false })`, браузер не запускается. Запуск — по кнопке **«Запустить»** (`hasSession=true`) / **«Войти»** (`hasSession=false`) в футере диалога рядом с «Закрыть».

**Что изменилось:**
- `switchProfile(profileId, opts?: { launch?: boolean })` — default `true` (backward compat с failover-автоматикой). При `launch: false` — только `ps.activate()` + emit `profile:switched`, без `launch()` и без `loginInNewProfile()`.
- `gateway:profiles-activate(id, opts?)` — принимает `{ launch?: boolean }`, возвращает `{ success, data: { status: 'logged_in' | 'login_required' } }`.
- `gatewayLaunch()` (существующий IPC) — запускает **активный** профиль. Используется кнопкой «Запустить».
- `GatewayAccountsDialog`: `onSelect` (switch, `launch: false`) + `onLaunch` (по `hasSession`: `gatewayLaunch` или `profilesActivate(id, { launch: true })`).

**TD (pre-existing, не блокер):** `gatewayLaunch` отсутствует в `src/types/gateway.d.ts`, маскируется через `getApi(): any` в диалоге. Добавить при ужесточении типов.

**Связанные проблемы:** П1 (диалог пропадал при switch) — частично смягчено: switch теперь не рвёт браузер.

## Правило: DeepSeek UI не трогаем до универсального UI (2026-11-22)

`GatewayPage.tsx` и `TopControlPanel.tsx` — **только для DeepSeek**. Любые
multi-provider изменения — в отдельном `UniversalGatewayPage.tsx` или через
новые IPC-хендлеры без модификации существующих.

**Почему:** смешение провайдеров в одном компоненте ломает backward compat
и risk-ит рабочий DeepSeek-путь. Провайдер-выбор — часть универсального UI
(будущая сессия).

**Что можно:** новые хендлеры в `gatewayHandlers.ts` (`send-message-universal`,
`launch-provider-aware`), `providerId` в `ProfileService` (additive),
бейджи в списке профилей (визуальный индикатор, не переключатель).
