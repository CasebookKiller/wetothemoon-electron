## Проект

`wetothemoon-electron` — многомодульное Electron 44 + React 19 + PrimeReact + Vite +
TypeScript приложение. Модули: Gateway (DeepSeek), OSINT (Fremen Eye), Prana-Bindu
(fitness), Trading Assistant, Sietch (БД OSINT), Landsraad (судебные дела), Tasks (cron),

patchright (Chrome) + официальный DeepSeek API как второй канал для автономных агентов.

### 7. Multi-profile cache (готово в этом чате)

**Схема v8** была до нас (бан-чат): `profile_id` в `conversations`/`messages`,
`UNIQUE(profile_id, message_hash)`.

**`GatewayCacheService.ts` — 4 метода (наш патч):**
- `syncConversation(convId, title, incoming, opts?: { prune?, profileId? })` —
  `const profileId = opts?.profileId ?? 'default'`, прокинут в оба `INSERT`
  (`conversations` — 9-я колонка, `messages` — 16-я)
- `listConversations(profileId = 'default')` — `WHERE archived = 0 AND profile_id = ?`
- `getMessageByHash(hash, profileId = 'default')` — `WHERE profile_id = ? AND message_hash = ?`
  (критично: v8 сняла `UNIQUE(message_hash)`)
- `searchMessages(query, limit = 50, profileId = 'default')` — FTS: `WHERE c.profile_id = ?
  AND messages_fts MATCH ?`; LIKE-fallback: `WHERE c.profile_id = ? AND m.content_plain LIKE ?`
- `updateStmt` **не тронут** — `profile_id` устанавливается при INSERT, обновлять не нужно

**`gatewayHandlers.ts` — 5 вызовов (наш патч):**
- `gateway:cache-sync` (2×) — `profileId: ProfileService.getInstance().getActiveId()`
- `gateway:cache-list` — `cache.listConversations(getActiveId())`
- `gateway:cache-search` — `cache.searchMessages(query, limit, getActiveId())`
- `gateway:cache-save` — `{ profileId: getActiveId() }`

## 🐞 Найденные проблемы (новые в этом чате)

### П1. Диалог пропадает при переключении профиля (UX, не баг)

**Симптом:** открыт диалог под `request.tel` → переключение на `default` → диалог
исчезает, общаться нельзя.

**Причина:** `gateway:get-conversations` → `service.getConversations()` — **live из Chrome**,
а не из кэша. При switch Chrome перезапускается на другой учётке DeepSeek → в нём этого
диалога нет → список пуст. `profile-switched` handler (`GatewayPage.tsx:1183`)
**сбрасывает** открытый диалог + перезагружает список из нового Chrome.

**Это правильно** с точки зрения multi-account (разные аккаунты DeepSeek = разные
истории), **но плохо** с точки зрения UX — пользователь теряет диалог без объяснения.

**Варианты фикса:**
- **A (5 мин):** предупреждение в `GatewayAccountsDialog.onActivate` перед switch, если
  открыт диалог
- **B (30–40 мин):** сайдбар из `cache.listConversations()` без фильтра, все диалоги
  всех профилей + бейдж профиля + при клике на чужой — `gatewayProfilesActivate` +
  ждать `profile-switched`. **Естественно после v9**
- **C (10 мин):** модалка подтверждения при клике на чужой диалог

**Рекомендация:** сейчас A, после v9 — B.

## Архитектурные принципы (не нарушать)

1. **Три режима:**
   - Web-чат (ручной через Yandex/Chrome CDP) — основной для общения
   - API-чат (ручной через DeepSeek API) — резерв + UI
   - Agents (авто через API) — pipeline, память, training
2. **Workspace per conversation (вариант C):** в каждом чате свой набор активных
   directions. `global/project/submodule` всегда общие, direction'ы — переключаются
3. **Мозг ≠ один:** DeepSeek API — оркестратор, Ollama — тренируемые модели
   (direction `training/finetune-ollama`)
4. **Изоляция каналов:** при работе над API-каналом web не трогаем, и наоборот
5. **Двусторонняя связь окон** (event bus) — обязательно для будущего
6. **Долговременная память — многоуровневая:** global → project → submodule → module
   → direction + state. Каждый узел версионируется (`context_versions`), привязан
   к git commit, может иметь `summaryFile` для компактной инъекции
7. **Структура контекста (5 уровней) — ложится на `key.split('/').length`:**
   ```
   L0 common → L1 project → L2 submodule → L3 module → L4 direction
   ```
   `chainOf` в `contextBuilder` уже это умеет. **Не менять архитектуру.**
8. **Правило «найти/заменить»** — правки в стиле find/replace, не «вставь в конец»

## Известные подводные камни

- **Electron SUID sandbox:** если `npm run dev` падает с `FATAL: The SUID sandbox helper`,
  фикс: `sudo chown root:root node_modules/electron/dist/chrome-sandbox && sudo chmod 4755
  node_modules/electron/dist/chrome-sandbox`. Или `--no-sandbox` для dev (менее безопасно)
- **Chrome profile пустой:** при yandex→chrome `chrome-profile/` создаётся пустым.
  Первый запуск DeepSeek — `/sign_in`, логиниться руками. WAF выдаст новый
  `aws-waf-token` под Chrome-fingerprint. Yandex-сессия сохраняется в `yandex-profile/`
- **Клонировать cookies Yandex→Chrome бесполезно:** `aws-waf-token` привязан к
  fingerprint. Chrome отвергнет
- **`npx tsc` гоняет всё дерево** — фильтруй по нашим файлам
- **`npm run dev`, не `npm start`** — в этом проекте `npm start` иногда ведёт не туда
